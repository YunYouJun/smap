# 产品路线图

最后整理：2026-07-31。

本文用于维护 SMAP 的产品方向和优先级，不代表固定发布日期。具体版本可以根据验证结果调整，但每个阶段都应交付一条可完整体验、可测试的用户路径。

## 产品目标

SMAP 当前定位为可公开体验的星际导航地图原型。近期最重要的目标不是继续增加页面，而是完成一条可信的核心闭环：

```text
选择起终点
  → 比较路线与风险
  → 启动模拟导航
  → 经过航段与服务点
  → 到达目的地
  → 保存行程、收藏或偏好
```

功能排序遵循以下原则：

1. 核心出行闭环优先于新增入口。
2. 状态和反馈的完整性优先于页面数量。
3. 模拟能力必须明确标注，避免让静态数据看起来像真实服务。
4. PC 和移动端可以采用不同布局，但共享同一份领域状态和行为。
5. 通用数据能力优先沉淀到 SDK，具体展示和文案保留在应用层。

## 当前能力与缺口

| 领域 | 当前能力 | 下一阶段目标 |
| --- | --- | --- |
| 路线 | 起终点搜索、路线比较、偏好选择、航段推进、暂停恢复、事件和到达摘要 | 更完整的航段级详情与推荐差异说明 |
| 探索 | POI 选择、详情、图层开关 | 一键设为起点/终点/途经点、收藏、加入路线 |
| 打车 | 车型、报价、接驾信息、响应结果 | 完整订单状态机、取消与完成、订单沉淀 |
| 账号 | YunLeFun 登录入口与账号状态 | 收藏、订单、偏好持久化以及真实空状态 |
| 星历 | 静态数据与可选 JPL Horizons 数据源 | 日期控制、更新时间、动态位置和回退说明 |
| SDK | 路线、POI、图层、事件和数据源 API | 状态序列化、自定义数据源示例、集成演练场 |

## M1：完成可运行导航闭环

这是最推荐优先实施的阶段。

### P0：导航模拟状态机

- [x] 将当前布尔值扩展为 `idle`、`navigating`、`paused`、`arrived` 状态。
- [x] 按航段推进当前位置、剩余时间、进度和下一个途经点。
- [x] 使用可调速的虚拟时钟推进，不依赖真实航行时长。
- [x] 支持开始、暂停、继续、结束、重新开始和重新规划。
- [x] 在经过风险区或服务点时生成明确事件，并同步更新地图与时间线。
- [x] 每个事件在单次导航中只触发一次，并能从事件中定位对应航段或地点。
- [x] 到达后生成保留在当前会话中的行程摘要；持久化历史留到 M2。
- [x] 为状态转换、暂停恢复和到达流程增加单元测试与 E2E。

状态转换约定：

| 当前状态 | 操作或条件 | 下一状态 | 数据处理 |
| --- | --- | --- | --- |
| `idle` | 开始 | `navigating` | 从首个航段和零进度开始 |
| `navigating` | 暂停 | `paused` | 保留进度、事件和剩余时间 |
| `paused` | 继续 | `navigating` | 从暂停位置继续 |
| `navigating` / `paused` | 主动结束 | `idle` | 清空本次进度，不生成完成记录 |
| `navigating` | 到达终点 | `arrived` | 进度设为 100%，生成会话内行程摘要 |
| `arrived` | 重新开始 | `navigating` | 清空旧进度和事件，从当前路线重新开始 |
| 任意状态 | 重新规划 | `idle` | 重置导航运行态，保留新的路线选择 |

M1 的端到端验收场景：

1. 选择一条包含风险点和服务点的路线。
2. 开始导航，确认地图、时间线、剩余时间和当前航段同步推进。
3. 经过风险点时只出现一次对应事件。
4. 暂停后进度停止，继续后从原位置恢复。
5. 到达后进入 `arrived`，显示 100% 进度和行程摘要。
6. 重新开始后清除上一轮运行事件，并能再次完整到达。

### P0：路线详情

- 展示逐段路线、转向或跃迁提示、风险等级和服务点。
- 说明推荐路线与备选路线的差异来源。
- 允许在详情中切换路线，并保持地图焦点和时间线同步。
- 在移动端使用可展开 sheet，在桌面端复用右侧信息区。

### P1：探索转化为路线操作

- 将 POI 设为起点、终点或途经点。
- 支持会话内收藏地点，并提供最近使用和已收藏筛选；刷新后的持久化留到 M2。
- 从探索页进入打车时复用当前地点与路线。
- 为不可达地点、重复途经点和空搜索提供明确反馈。

### P1：演示数据诚实标识

- 对静态星历、模拟报价、模拟订单和示例个人数据使用一致的“演示”标识。
- 未登录时展示真实空状态，不显示看似属于当前用户的固定订单和资产。
- 为演示状态提供一键重置，便于测试和公开展示。

## M2：连接账号、订单与动态星图

### P1：个人数据持久化

- 先以本地存储实现收藏、最近路线、导航偏好和演示订单。
- 登录后再将本地状态与 YunLeFun 账号数据合并。
- 明确冲突策略、退出登录后的数据保留策略和清除入口。
- 个人中心根据登录状态展示空状态、同步状态和失败恢复操作。

### P1：打车订单状态机

- 使用 `quoted`、`requesting`、`accepted`、`arriving`、`in-transit`、`completed`、`cancelled` 表达订单状态。
- 为请求中、超时、取消、重新呼叫和完成提供独立反馈。
- 完成或取消后写入订单记录，并能从“我的”页重新查看。
- 所有订单继续保持模拟性质，不接入支付或真实调度。

### P1：可控时间与动态星历

- 增加日期或时间控制器，允许查看不同时间的天体位置。
- 明确展示数据来源、更新时间、缓存状态和静态回退原因。
- 星历更新时保持用户选择、路线和地图视角稳定。
- 对远端数据失败、部分天体失败和超时增加可恢复状态。

### P2：可分享路线

- 将起终点、途经点、路线策略和选中图层序列化到 URL。
- 支持复制链接、恢复路线和处理失效地点。
- SDK 提供对应的序列化与解析 API，应用只负责交互。

### P2：离线与可安装体验

- 增加 Web App Manifest、应用图标和安装入口。
- 缓存应用壳、静态星图和最近使用路线。
- 明确区分离线可用功能与需要登录或远端星历的功能。

## M3：强化 SDK 与可扩展生态

- 提供最小自定义数据源示例，演示接入自定义航点、路线和 POI。
- 增加 SDK playground，允许调整路线策略并查看事件输出。
- 提供数据校验和错误诊断，避免无效航点或断裂路线静默进入 UI。
- 支持导入、导出一份可版本化的 SMAP 数据集。
- 为 SDK 的公开 API 建立兼容性测试和迁移说明；1.0 前的破坏性变更必须在 minor 版本中记录。

M3 的最小验收路径是：示例应用加载一份外部数据集，通过校验后完成路线规划，收到导航事件，并能将同一份数据无损导出再导入。兼容性测试至少覆盖当前版本与上一个已发布 minor 版本。

## 暂不推荐

以下方向当前投入较大，但不能优先改善核心体验：

- **真实支付和快船调度**：在导航闭环和订单状态机稳定前，不应引入交易与履约风险。
- **完整社交系统**：动态、关注和排行榜会模糊地图产品的核心定位。
- **全量 3D/WebGL 重构**：可以作为后续视觉增强，但不应替代路线、状态和数据模型建设。
- **通用 AI 助手入口**：只有当它能明确缩短路线选择或风险解释流程时才值得加入。
- **大型账号后台**：先验证收藏、订单和偏好三类最小数据，再决定服务端模型。

## 推荐的下一项开发任务

下一步优先实现“路线详情与推荐差异说明”。直接复用已经完成的导航航段和事件数据，在桌面右侧信息区与移动端可展开 sheet 中展示逐段提示、风险、服务点，以及推荐路线相对备选路线的取舍原因。

这一项仍可完全静态实现，不需要真实定位、后台导航、支付或服务器同步。完成后再推进“探索地点一键设为起点、终点或途经点”，把路线规划与探索页连成第二条可验证闭环。
